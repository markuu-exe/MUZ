The client also accepts the `NEXT_PUBLIC_SUPABASE_URL` and
`NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` names (`vite.config.ts` exposes both
prefixes). Prefer the `VITE_` names in new setups. The anon/publishable key is
public by design; RLS is what protects the data. The `service_role` key must
never be put in any client env var.

If either variable is missing, the app shows
"MUZ configuration error: set VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY (see docs/ENVIRONMENTS.md)."
instead of a blank page (DEF-004, `src/configGuard.ts`). Tests, typecheck,
`vite build` and the seed check do not need the variables, so CI has none.

## CI

`.github/workflows/ci.yml` runs on Ubuntu with Node 22: `npm ci`, `npm test`,
`npx tsc -p tsconfig.json`, `npx vite build`, `npm run seed:lessons:check`,
`node scripts/check-bundle-size.mjs`. The token is read-only
(`permissions: contents: read`), and a new push to a PR branch cancels that
branch's run in progress.

The bundle-size check sums `dist/assets/index-*.js` and `dist/assets/index-*.css`
and fails above 5 MB (5 × 1024 × 1024 bytes) or when there are no such files.
Measured on the T-05 branch: 0.84 MB (878015 bytes; 0.88 MB in decimal units).
The whole `dist/` is about 44 MB because of `public/models` (the wasm files and
the pose model); those are not part of the check.

**NOT DONE:** "a failing PR blocks merge" needs branch protection on `main`
with the CI check required. A has not approved turning that on, so today a red
CI run is advisory only.
